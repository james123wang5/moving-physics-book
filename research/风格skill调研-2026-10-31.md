# 把“墨线立体互动书”风格做成 skill：调研（2026-10-31）

目标：把本项目（仿 Every Joule 风格的《抛体运动》互动书）的风格打包成一个 Agent Skill。别人装进自己的 AI（Claude Code、Codex、Cursor 等），给出自己的内容，AI 先问几个关键问题（不答就用默认），然后做出同风格的互动书网站。

## 1. 内核

- **字面层**：一个 skill 包（SKILL.md + 资料 + 模板 + 脚本）。
- **功能层**：输入是用户的内容和少量选项，输出是一个能跑、能发布的互动书网站。用户是想做互动讲解的老师、开发者和创作者。
- **机制层**：风格 = 可复用的引擎 + 设计规范 + 内容格式 + 写装置的接口。skill 负责问答、搭脚手架、按规范写内容和装置、截图自查。
- **换壳方向**：设计系统 skill、可探索式讲解的写作框架、AI 生成交互课件、three.js 脚手架 skill。

## 2. 结论

- **没有人做过这个。** GitHub、网页、X 上都没找到把 Every Joule 风格做成模板或 skill 的项目。现有的都是一次性仿作，内容写死，不能换内容。
- **需求是明确的。** 原作 X 帖下有人问“下一个学科做什么”“有没有中文版”“我也想照这个方法做自己的课程”。
- **同类 skill 有现成的结构可学。** 能把一种独特画风复现出来的 skill，都带着可运行的模板代码，而不只是文字说明。只靠文字的 skill（如 frontend-design、AetherViz）做不出特定画风。
- **作者没有开源。** 原作仓库只有压缩后的成品，没有许可证。skill 里只能放我们自己的代码，注明“灵感来自 Every Joule”，不放原作的代码、文字和音效。

### 内容格式和装置接口的先例

- **Mathigon 教材**：每节一个 Markdown，按步骤切分；每节的交互代码按步骤 id 挂载，引擎给它一个状态对象，文字里可以引用实时数值。和我们“左页文字 + 右页装置 + 你的数据”的结构最像。代码保留所有权利，只能借鉴做法。
- **MyST 的 anywidget**：交互组件是一个导出 `render({model, el})` 的 ES 模块，状态用 `model.get/set/on`。这是最干净的插件接口。
- **论文和比赛作品**（SimStep、LivePhys、chalkbox 等）：完全让 AI 自由写物理动画，可靠性很低（SimuScene 测出最好的模型也只有约 21.5% 通过）。可靠的做法是：结构化的部分用格式校验；装置代码可以自由写，但必须在无头浏览器里跑起来、截图，检查没有报错、数值和公式对得上。

## 4. 对我们 skill 的启发

1. **skill 必须带引擎模板。** 我们的书本、墨线、立起来、控制条、放大镜、音效约 5 千行，AI 不可能每次从零写到这个水准。skill 只负责让 AI 写内容和装置。
2. **SKILL.md 只写流程和要点，细节放到 references/。** SKILL.md 正文控制在 500 行以内，用到时再读对应的参考文件。
3. **内容用固定格式，加校验脚本。** 课文、公式、关键词、预测、测验、索引都用数据写，脚本检查缺项和格式错误。
4. **问答一次问完（最多 4 个），推荐项放第一个，写明默认值；回复“默认”就全用默认。** 装置方案是最贵的部分，必须让用户确认。先做第 1 课给用户看，满意再做其余。
5. **截图自查闭环。** 每做完一课，脚本在无头浏览器里翻到这一页、跑演示、截图、收集报错，AI 自己看图修。
6. **署名和许可证。** 注明灵感来自 Every Joule；不用原作名字当产品名；不放原作的代码、文字、音效。我们的音效是 Freesound 上的 CC0 录音，可以带上并附出处。
