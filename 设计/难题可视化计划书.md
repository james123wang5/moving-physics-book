# 高考物理难题可视化 · 计划书（草案，待确认）

2026-10-31

---

## 零、一句话

学生把一道难题交给自己的 AI，AI 按我们的格式写出"题目里有什么"和"每一问怎么解"；我们的引擎自己把题目算一遍，逐个核对 AI 写的数，再按小问播放动画，配受力、v-t 图、能量变化和推导过程。我们不付任何模型费用。

**三条底线**

1. **动画由引擎算，不照着答案画。** 所以动画一定符合物理规律。
2. **正确性靠核对，不靠 AI 的水平。** 免费模型解不对压轴题没关系，只要条件抄对，引擎就能算对；抄错了，官方答案会拦下。
3. **AI 不写任何代码。** 它只输出一份固定格式的 JSON。

第五章讨论里做的板块小样，已经证明"一行参数 → 动画、图表、每问推导"这条路走得通。这份计划要做的，是把它从"一种题型"变成"部件可以任意组合"。

---

## 一、学生用起来是什么样

1. **复制提示词**：在网站上点"复制提示词"。
2. **问自己的 AI**：打开豆包、DeepSeek 等免费 App，发题目截图（有官方答案就一起发）和提示词。
3. **贴回来**：把 AI 的回复整段粘贴回网站。
4. **确认场景**：网站画出一张场景示意图，列出每个条件和它在题目里的原文。学生看一眼，没读错就点"确认"。
5. **看结果**：
   - 全部对上：每一问一页，动画和解题步骤同步播放。
   - 有对不上的：标红那一步，并给出一段"修复提示"，学生复制回 AI，让它改完再贴回来。

有官方答案时，AI 以官方答案为准，把过程整理成老师讲题的口吻（这就是"润色"，由学生的 AI 完成）。没有官方答案时，AI 自己解，引擎负责复核。

## 二、系统由哪几块组成

```
题目截图 + 官方答案
        │  学生的 AI（按我们的提示词）
        ▼
   一份 JSON：场景 + 每问问什么 + 解题过程
        │
        ├─► ① 读入与校验：宽容解析，格式不对就生成修正提示
        ├─► ② 场景预览：示意图 + 条件原文对照，学生确认
        ├─► ③ 理想物理引擎：搭场景、模拟、自动分阶段、记能量账
        ├─► ④ 核对器：逐步核对过程里的数，和官方答案对照
        └─► ⑤ 播放器：每问一页，动画 + 步骤高亮 + 受力 / v-t / 能量
```

另外两块不在流程里，但一样重要：

- **⑥ 提示词包**：给学生 AI 的说明，包括格式、部件清单、物理量词表、两个完整示例。
- **⑦ 标准集**：约 20 道带官方答案的真题，每道题都是一个自动测试。引擎每改一次，全部重跑一遍。

## 三、每一块怎么做

### 3.1 格式：一份 JSON，三个部分

一次粘贴就够，所以把三部分放在同一份 JSON 里：

- **场景（scene）**：有哪些部件，怎么摆，怎么连，初始条件是什么。
- **问题（asks）**：每一问求的是什么量、在哪个时刻或哪一段、参考答案。
- **解题过程（solution）**：每一问分步写，每一步的结果都标明"这是哪个物理量"。

**每个数都附题目原文。** 例如 `[0.4, "", "动摩擦因数 μ=0.4"]`。这样场景预览时，学生能一眼看出 AI 有没有抄错。

**示例**（格式还没定，这里只是示意）

> 光滑水平面上有一块质量 M = 2 kg 的长木板 B，质量 m = 1 kg 的小物块 A 以 v₀ = 6 m/s 从左端滑上木板，A、B 间动摩擦因数 μ = 0.4，木板足够长，g 取 10 m/s²。(1) 求 A、B 共速所用时间；(2) 求全过程因摩擦产生的热量。

```json
{
  "spec": "v1",
  "constants": { "g": 10 },
  "scene": {
    "bodies": [
      { "id": "A", "kind": "block", "m": [1, "kg", "质量 m=1 kg 的小物块 A"],
        "v0": [6, "m/s", "以 v₀=6 m/s 从左端滑上木板"], "on": "B", "at": "B.left" },
      { "id": "B", "kind": "board", "m": [2, "kg", "质量 M=2 kg 的长木板 B"],
        "length": "long_enough", "on": "ground" }
    ],
    "surfaces": [ { "id": "ground", "kind": "flat", "mu": [0, "", "光滑水平面"] } ],
    "friction": [ { "between": ["A", "B"], "mu": [0.4, "", "A、B 间动摩擦因数 μ=0.4"] } ]
  },
  "asks": [
    { "id": "1", "text": "A、B 共速所用时间",
      "find": { "qty": "time", "event": { "type": "same_velocity", "bodies": ["A", "B"] } },
      "answer": [1, "s"] },
    { "id": "2", "text": "全过程因摩擦产生的热量",
      "find": { "qty": "heat", "by": { "friction": ["A", "B"] }, "until": "end" },
      "answer": [12, "J"] }
  ],
  "solution": {
    "1": [
      { "say": "A 受向左的滑动摩擦力，做匀减速运动",
        "tex": "a_A=\\mu g=4\\ \\mathrm{m/s^2}",
        "claim": { "qty": "acc", "body": "A", "during": "before:same_velocity", "value": 4 } },
      { "say": "B 受向右的滑动摩擦力，做匀加速运动",
        "tex": "a_B=\\dfrac{\\mu m g}{M}=2\\ \\mathrm{m/s^2}",
        "claim": { "qty": "acc", "body": "B", "during": "before:same_velocity", "value": 2 } },
      { "say": "共速时两者速度相等",
        "tex": "v_0-a_A t=a_B t \\Rightarrow t=1\\ \\mathrm{s}",
        "claim": { "qty": "time", "event": "same_velocity", "value": 1 } }
    ],
    "2": [ "……" ]
  }
}
```

**格式要照顾的几件事**

- **每一问可以改条件。** 很多题第 (3) 问会说"若传送带速度改为……"，所以每一问可以带自己的改动，引擎为这一问单独再算一遍。
- **题目给的近似照用。** g 取 10、sin37° = 0.6 写进 `constants`，引擎就按这个算，不然会和答案差一点。
- **反过来求条件的题。** 比如"由图乙的 v-t 图像求 μ"：把官方答案求出的 μ 填进场景，同时把图像上的几个关键点作为"观测"写进去。引擎模拟后，这些点对得上，就说明这个 μ 是对的。
- **AI 不写阶段的起止时间。** 它只用事件名称来指"哪一段"，比如"共速之前""弹簧最短时"，具体时刻由引擎算。

### 3.2 理想物理引擎

**不用游戏里的物理引擎。** 它们一帧一帧近似，数值会漂，对不上 4/3 s 这种答案。我们自己写一个"理想物理"引擎。

**部件（积木）**：第一版的清单如下，最终以标准集统计为准。

| 类别 | 第一版（力学） | 第二版（电磁） |
|---|---|---|
| 物体 | 滑块、木板、小球 | 带电粒子、导体棒 |
| 面和轨道 | 水平面、斜面、圆弧（含竖直圆周）、传送带（水平和倾斜）、挡板 | — |
| 连接 | 轻弹簧、轻绳和滑轮 | — |
| 力和场 | 重力；恒力，可在某时刻或某事件时撤去或改变 | 匀强电场、匀强磁场，可分区域（半平面、条带、矩形、圆形） |
| 电路 | — | 平行导轨（水平和倾斜）、电阻、电容 |

**怎么算**

- **分段精确算。** 每一段里受力情况不变，就用公式直接算：匀变速、简谐振动、匀速圆周、指数衰减（导体棒）。只有少数受力随时都在变、没有简单公式的情况，才用高精度数值积分。
- **转折点精确求出。** 共速、滑离、碰撞、弹簧最短、离开轨道、进出场区、撤去外力，引擎都会检测，并把转折时刻精确解出来，然后换下一段。
- **谁和谁相对滑动，逐个试。** 每到转折点，把"一起动"和"相对滑动"的各种组合都试一遍，选出唯一说得通的那个（需要的静摩擦力不超过最大静摩擦力）。叠放的物体一般不超过三个，组合最多二十几种，很快。
- **结果显示成分数和根号。** 自动识别 a/b、a√b/c、含 π 的形式。实在不是整齐的数，就显示小数。
- **记能量账。** 每个力做的功、摩擦生热、焦耳热、各种势能都记下来。最后自动检查能量守恒，这是引擎给自己的检查。
- **求范围和最值。** 例如"v₀ 至少多大""μ 满足什么条件"：引擎把参数从小到大扫一遍，再用二分法找出临界值。播放时给一个滑块，可以拖到临界状态看。
- **自动列每一段的方程。** 引擎知道这一段谁和谁接触、受哪些力，就能列出"对 A：μmg = m·a_A"这样的式子并代入数值。它作为"引擎视角"折叠在每一段旁边；AI 的过程缺了某一步时，也可以拿它补上。
- **不依赖浏览器。** 引擎在命令行就能跑，所以每道标准题都能写成自动测试。

### 3.3 核对器

- **物理量词表。** 每一步的结果都要标明它是哪个量，从我们的词表里选。

| 类别 | 词表里的量 |
|---|---|
| 运动 | 时间、位置、速度、加速度、位移、路程、相对位移（划痕长度） |
| 力 | 支持力、摩擦力、拉力、弹力、安培力、洛伦兹力 |
| 功和能 | 功、功率、动能、重力势能、弹性势能、电势能、摩擦生热、焦耳热 |
| 动量 | 动量、冲量 |
| 电磁 | 电动势、电流、电荷量、电压、轨道半径、周期、偏转角、出射位置 |
| 特殊问法 | 最大值、最小值、取值范围 |

- **事件名称表。** 共速、滑离、到达端点、碰撞、弹簧最短、弹簧最长、恢复原长、离开轨道、最高点、最低点、进入场区、离开场区、撤去外力、达到最大速度。AI 用这些名称指明"哪一段""哪个时刻"。
- **三种结果。**
  - ✓ 对上。
  - ✗ 对不上，标红。
  - ○ 没标物理量，或者是纯代数变形，没法核对，显示灰色，不算错。
  - 每一问的最终答案必须标物理量，必须核对。
- **对不上时自动排查。** 先看常见原因：g 取 9.8 还是 10、角度近似、正负方向、单位、保留位数。查到了就直接说"这一步用了 g = 9.8，题目要求取 10"。
- **引擎和官方答案对不上，多半是场景读错了。** 这时回到场景预览，把可疑的条件和原文并排列出来让学生看。
- **修复提示。** 自动生成一段话，写清哪一步、哪个数、引擎算出来是多少。学生复制回 AI 就行，最多来回 2 轮；还不行，就让学生在条件表里直接改数。
- **结果标签。**
  - **已核验**：引擎、官方答案、解题过程三者一致。
  - **引擎复核一致**：没有官方答案，引擎和过程一致。AI 有可能一开始就把条件读错，和引擎"错得一致"，所以不叫"已核验"。
  - **有问题**：有红色步骤没解决。
- **暂不支持。** 题目用到清单外的部件，直接说清楚缺哪一个，不硬做。

### 3.4 播放器

- **场景预览**：静态示意图，加条件表（数值、单位、原文），下方是"确认"按钮。
- **每一问一页**：
  - 动画只播这一问对应的那段时间。
  - 旁边是解题步骤。播到哪一段，就高亮哪一步；点某一步，动画跳到对应时刻。
- **叠加层按问法自动选**：

| 问法 | 自动叠加 |
|---|---|
| 求时间、速度、加速度 | 受力箭头，v-t 图和游标 |
| 求位移、划痕长度 | v-t 图下的面积，或两条线之间的面积；画面上画出划痕 |
| 求功、热量、能量 | 能量柱：各种能量怎么转化，热量从哪来 |
| 碰撞 | 碰前碰后的动量柱 |
| 求范围、最值 | 参数滑块，临界值处做标记 |
| 带电粒子 | 轨迹、圆心、半径；不在一个平面里运动时切到 3D |

- **先预测，再播放**：每一问开头一道小预测题，例如"你觉得 A 会从 B 上滑下来吗"，由 AI 顺带写出。这样学生是先想、再看，不是只看动画。
- **播放控制**：播放、暂停、慢放、逐段。
- **画面**：第一版用平面示意图，像教辅插图，力求清楚；带电粒子的螺旋线、磁聚焦这类再用 3D。界面好不好看放到后面。

### 3.5 提示词包

- **内容**：格式说明、部件清单、物理量词表、事件名称表、两个完整示例。
- **规则**：
  - 每个数照抄，并附原文。
  - 统一用国际单位。
  - 不要自己算阶段时间。
  - 有官方答案时，以官方答案为准。
  - 过程要像老师讲题。
- **宽容解析**：AI 的回复里常有代码框、中文引号、多余逗号，网站都能自动处理。
- **格式错了**：自动生成"请按以下几点修正"的提示词，让学生复制回去。
- 格式定义只写一份，同时用来校验 JSON 和生成提示词，两边不会对不上。

### 3.6 题库（后面再做）

- 核验通过的题保存成文件，有固定链接，后来的人直接看，不用重新生成。
- 第一批常见真题，可以由我在 Claude Code 里用你的订阅批量做好，不另付费。
- 公开题库之前，要先确认真题的版权问题。

## 四、分步计划

工作量按每天集中做来估，主要受我的使用额度限制，只是粗估。每一步做完都有能看、能测的东西。

| 步 | 做什么 | 做完的标准 | 大致工作量 |
|---|---|---|---|
| 0 | 收集约 20 道带官方答案的真题（力学约 12 道、电磁约 8 道）；统计部件、事件、问法；定格式第一版；我手写 20 份标准 JSON；写提示词初版，用豆包和 DeepSeek 免费版试 3–5 道 | 部件清单和格式定下来；初步知道免费模型能不能按格式输出 | 2–4 天 |
| 1 | 力学引擎（只有计算，没有画面）：滑块、木板、斜面、传送带、弹簧、碰撞、平抛、竖直圆周、撤去外力、绳和滑轮 | 标准集里的力学题，官方答案全部算对 | 1.5–2.5 周 |
| 2 | 核对器、解题过程格式、提示词定稿；免费模型正式实测 | 标准集的官方解答全部核对通过；拿到三个数：条件抄对的比例、核对通过的比例、平均修复几轮 | 约 1 周 |
| 3 | 播放器第一版（平面）：场景预览、每问动画、步骤同步、受力、v-t 图、能量柱 | 力学标准题能从"粘贴 JSON"一路走到每问动画 | 1–1.5 周 |
| 4 | 求范围、求最值、分情况讨论 | 标准集里这类问都能找到临界值，并能拖动演示 | 约 1 周 |
| 5 | 电磁：电场、分区域磁场、带电粒子（含 3D）、导体棒加导轨加电阻和电容 | 标准集里的电磁题全部算对、核对通过、能播放 | 2–3 周 |
| 6 | 题库、分享链接、界面设计打磨 | 到时再定 | — |

**两个检查点**

- **第 0 步结束**：如果免费模型连场景部分都抄不对，先改格式（比如拆成几次问、增加表单填写），再动引擎。
- **第 2 步结束**：根据实测的三个数决定，是继续复制粘贴的路线，还是再加一条"学生自带 key、网页直接调用"的路线（费用由学生自己出，我们仍然不付）。

## 五、先不做的事

- 不调用任何要我们付费的模型，也不搭服务器。
- 不让 AI 写动画代码。
- 先只做力学和电磁的计算大题；选择题、实验题、光学、热学、原子物理以后再说。
- 不做账号和支付。
- 界面先求清楚，不求好看。

## 六、风险和应对

| 风险 | 应对 |
|---|---|
| 免费模型标物理量时标错或不标，"逐个核对"就落空 | 没标的显示灰色，不算错；最终答案强制标；实测后再调整词表的粗细 |
| 题图读错，这是最大的错误来源 | 场景预览加原文对照，学生确认；官方答案兜底 |
| 部件组合千变万化，总有清单外的题 | 明确说出缺哪个部件；按真题里出现的频率逐个补 |
| 引擎自己有 bug | 标准集回归测试，每次改动全部重跑；能量守恒自检 |
| 没有官方答案时，AI 和引擎"错得一致" | 标"引擎复核一致"，不标"已核验"；强制学生确认场景 |
| 学生看懂动画就以为自己会了 | 每问先预测、再播放 |
| 工作量大，额度有限 | 按步骤推进，每步都有能用的成果；续做说明随时更新，换会话也能接上 |

## 七、技术选型

- **新建一个独立的项目文件夹**，和互动教材分开。互动教材的三维书本代码这里用不上；KaTeX 公式排版、三维舞台代码（以后电磁 3D 用）会搬过来。
- **TypeScript**：部件、物理量、事件的种类很多，用它能让很多错误在写代码时就被发现。
- **平面画面用 SVG**：线条和文字清楚，也方便导出图片。3D 用 three.js。
- **纯静态网页**：不需要服务器，可以免费托管。
- **参考的开源项目**：
  - PhysicsOS（Apache-2.0）：场景合同、校验器、拒绝不支持题型的做法。
  - edulab（Apache-2.0）：受力箭头、v-t 图、能量柱的画法。
  - WorldByCode（MIT）：AI 只输出 JSON，加修复循环。
  - 用到它们的代码时，按协议注明出处。
